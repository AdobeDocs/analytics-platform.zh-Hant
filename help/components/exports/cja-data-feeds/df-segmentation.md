# 資料摘要中的細分

{{release-limited-testing}}

Customer Journey Analytics中的資料摘要支援分段，可讓您篩選每個摘要傳送中包含的列。 您可以在資料檢視層級、摘要層級或兩者套用區段。

## 區段的套用位置

您可以在兩個位置將區段套用至資料摘要：

- **資料檢視**：在資料檢視中設定的區段，適用於使用該資料檢視的所有摘要。
- **資料摘要**：除了任何資料檢視區段外，還直接套用至個別摘要的區段。

兩者皆已設定後，Customer Journey Analytics會將其合併，只有符合兩個區段的列才會納入摘要輸出中。

## 日期範圍區段

資料摘要支援參考日期範圍的區段。 不過，此行為與Analysis Workspace有一項重要不同： **區段中的日期範圍條件不會覆寫摘要的報表日期範圍。**

在Analysis Workspace中，套用日期範圍區段會變更作用中報告期間，以符合區段的日期範圍。 在資料摘要中，報告時段一律由摘要的排程傳送（每小時或每日）定義。 具有日期範圍條件的區段會篩選該視窗中的列 — 它不會移動或展開視窗本身。

此設計是有意為之。 允許日期範圍區段覆寫報告期間，可能會導致每小時的摘要傳遞比預期大得多的資料期間，導致資料重複或輸出量過多。

### 範例

**範例1 — 包含特定日期事件的區段**

假設您套用的區段只傳回7月1日的事件，並執行7月22日的摘要：

- 摘要的傳送期間仍為7月22日。
- 區段會篩選掉所有列，因為7月22日視窗內的事件均不符合7月1日的條件。 摘要會執行，但不會傳送任何列。
- 如果您在7月1日執行回填，區段會如預期般運作，只有符合7月1日條件的事件才會納入其中。

**範例2 — 從特定日期排除事件的區段**

假設您套用區段，該區段排除7月1日訂購的所有事件，並執行7月22日的摘要：

- 此區段適用於7月22日的資料。 由於「7月22日」視窗中沒有任何「7月1日」事件，因此不會排除任何事件，且會傳送所有列。
- 如果您在7月1日執行回填，區段會如預期排除相關列。

## 包含多個條件的區段

對於結合日期範圍條件與其他條件的區段，Customer Journey Analytics僅以列篩選條件評估日期範圍部分，而不是以報表時段覆寫評估。 區段中的所有條件都會在摘要的傳遞期間接受。

## 區段資格和回顧日期範圍

對於使用人員或工作階段容器的區段，資格由&#x200B;**回顧日期範圍**&#x200B;設定決定，而不只是傳遞期間。 如果某個人符合回顧日期範圍內的資格，則包含該個人在傳遞期間內的所有事件。 容器設定會決定範圍：

- **事件容器**：僅包含符合傳遞期間內的區段條件的事件。
- **工作階段容器**：已包含傳遞期間中合格工作階段的所有事件，這些事件會在回顧日期範圍內評估工作階段資格。
- **人員容器**：在回顧日期範圍內符合資格的任何人員，都會包含傳遞期間內的所有事件。

如需有關回顧日期範圍以及它如何影響區段資格的詳細資訊，請參閱[建立資料摘要](/help/components/exports/cja-data-feeds/create-feed.md)。

## 與Analysis Workspace比較

| 行為 | Analysis Workspace | 資料饋送 |
|---|---|---|
| 日期範圍區段會覆寫報告期間 | 是 | 無 |
| 區段篩選報告時段內的列 | 是 | 是 |
| 資料檢視區段適用 | 是 | 是 |
| 直接套用至傳遞的其他區段 | 無 | 是 |
